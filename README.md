# AuthReflector

One account. One login. Every app.

AuthReflector is the single sign-on (SSO) identity provider for all our projects (SplitMate, CodeQuror, and whatever comes next).
Users sign in once at `accounts.<domain>`. Every app sends users there to log in and gets back signed tokens, so no project
ever has to build login, sign-up, social login or password reset again.

It is an OpenID Connect provider built with Spring Authorization Server. The design, requirements and decisions are in
[docs/AuthReflector-Design-Doc-v0.4.docx](docs/AuthReflector-Design-Doc-v0.4.docx), which is generated by
[docs/build_design_doc.py](docs/build_design_doc.py). To understand how it all works, read the learning guide
[docs/AuthReflector-Learning-Guide.docx](docs/AuthReflector-Learning-Guide.docx) (concepts, code map, and step-by-step dry runs
with failure cases), generated by [docs/build_learning_doc.py](docs/build_learning_doc.py).

## What works today

| Endpoint / page | Purpose |
|---|---|
| `/register`, `/login`, `/account` | React pages: sign up (signed in automatically), sign in, signed-in page with sign out |
| `POST /api/v1/auth/register` | Create an account (JSON) and start the session |
| `POST /login` | Spring Security form login (`email`, `password`, form-encoded), JSON `{redirectUrl}` or 401 |
| `GET /api/v1/me` | Who is signed in (401 when nobody) |
| `POST /logout` | End the session (204) |
| `GET /api/v1/auth/csrf` | Make sure the `XSRF-TOKEN` cookie exists |

Every POST needs the CSRF token: the value of the `XSRF-TOKEN` cookie sent back in the `X-XSRF-TOKEN` header
(the React app's API client does this automatically). The session cookie is `AR_SESSION`.

## Admin: registering apps

Apps are registered at runtime in the database: no config file, no restart.

1. Make your account an admin once, from the database (there is deliberately no API or UI for this):
   `./scripts/make-admin.sh you@example.com`, then sign out and in again.
2. Open http://localhost:9000/account → **Manage apps** → **New app**.
   - **With backend** (SplitMate, CodeQuror): gets a client secret, **shown once** (stored only as a hash).
   - **Frontend only** (Pincode, embeddings POC): no secret; the JS SDK uses PKCE.
3. Redirect URLs must be `https://`, or `http://127.0.0.1:<port>` for local development
   (OAuth 2.1 does not allow `localhost` here: open local apps at `http://127.0.0.1:<port>`).
4. Disabling an app blocks new sign-ins at once and ends its existing sessions.

## Adding SSO to a Spring Boot app (client starter)

1. Register the app on the admin page as **With backend**; redirect URL `http://127.0.0.1:<port>/login/oauth2/code/authreflector`,
   after-sign-out URL `http://127.0.0.1:<port>/`. Copy the secret (shown once).
2. Add the starter (built by [JitPack](https://jitpack.io) from a Git tag of this repo):

```xml
<repositories>
  <repository><id>jitpack.io</id><url>https://jitpack.io</url></repository>
</repositories>
<dependency>
  <!-- JitPack names it after the repository; versions are Git tags -->
  <groupId>com.github.mudit1024</groupId>
  <artifactId>authReflector</artifactId>
  <version>0.1.1</version>
</dependency>
```

3. Four lines of config:

```yaml
authreflector:
  client:
    issuer-uri: http://localhost:9000
    client-id: splitmate-web
    client-secret: ${SPLITMATE_CLIENT_SECRET}
    audience: splitmate-api
```

That's all: no login code in the app. You get:
- browser sign-in through AuthReflector (BFF: tokens stay on the server)
- `401` JSON for `/api/**` and a redirect to sign-in for pages
- bearer tokens for mobile apps and API clients, with the audience check
- `AuthReflectorUser user` as a controller parameter
- `ROLE_*` authorities from the roles
- `GET /auth/login`, `GET /auth/me`, `GET /auth/csrf` (send its token as `X-CSRF-TOKEN` on POST/PUT/DELETE)
- `POST /auth/logout`, which returns `{logoutUrl}`; open it in the browser to sign out at AuthReflector too
- `AuthReflectorSignInEvent` on every sign-in, to create or update the app's own user row

Source: [client/](client). A complete example app (one controller, one page, no security code) is in [demo-app/](demo-app): copy it to start a new project.

## Adding SSO to a frontend-only app (JS SDK)

1. Register the app on the admin page as **Frontend only**, with its page URL as redirect URL
   (e.g. `http://127.0.0.1:5175/`) and the same URL as after-sign-out URL.
2. Add the SDK (served by AuthReflector itself) and initialise it:

```html
<script src="http://localhost:9000/sdk/authreflector-web.js"></script>
<script>
  const auth = AuthReflector.create({ issuer: 'http://localhost:9000', clientId: 'pincode' })
  auth.init().then((user) => {
    // user = { id, name, email, roles } or null
    // signed in at AuthReflector already? then you're signed in here too (silent single sign-on)
  })
  // auth.signIn(), auth.signOut(), auth.getAccessToken(), auth.onChange(listener)
</script>
```

Open the app at `http://127.0.0.1:<port>` (not `localhost`), matching its registered redirect URL.
The SDK source is in [sdk/web](sdk/web); it is built into the jar by `./mvnw -Pui package`.

## Tech stack

| Layer | Choice |
|---|---|
| Backend | Java 21, Spring Boot 4.1.1, Spring Authorization Server (from A1) |
| Database | PostgreSQL 17, schema managed by Flyway |
| Login UI | React + TypeScript + Vite, served by the backend on the same origin (from AUTH-4) |
| Tests | JUnit 5, Testcontainers (real PostgreSQL 17 in Docker) |
| Local services | Docker Compose: PostgreSQL, Mailpit |

## Running locally

Prerequisites: Java 21, Docker Desktop (running).

```bash
# 1. Start PostgreSQL and Mailpit
docker compose up -d

# 2. Once: create a local token-signing key pair (backend/secrets/, git-ignored)
./scripts/generate-dev-keys.sh  # Git Bash on Windows

# 3. Run the backend (uses the "local" profile by default)
cd backend
./mvnw spring-boot:run          # Windows: mvnw.cmd spring-boot:run

# 4. Check it is up
curl http://localhost:9000/actuator/health      # {"status":"UP", ...}
```

### Login UI (React)

```bash
cd frontend
npm install
npm run dev        # http://localhost:5170, with hot reload
npm test           # Vitest + Testing Library
npm run lint
```

In development Vite (:5170) forwards server paths (`/api`, `POST /login`, `/oauth2`, ...) to Spring (:9000), so the browser
sees a single origin, the same as in production, where Spring serves the built UI itself.

To build one jar that contains both the backend and the UI:

```bash
cd backend
./mvnw -Pui package     # builds frontend/ with its own pinned Node and packs it into static/
java -jar target/authreflector-0.0.1-SNAPSHOT.jar
```

| Service | Address |
|---|---|
| AuthReflector | http://localhost:9000 |
| Login UI (dev server) | http://localhost:5170 |
| PostgreSQL | localhost:**5434**, database/user `authreflector` |
| Mailpit (caught emails) | http://localhost:8026 |

Ports are deliberately non-default so AuthReflector runs next to SplitMate (Postgres 5432, API 8080) and a native
Windows PostgreSQL service (5433).

## Tests

```bash
cd backend
./mvnw verify
```

Integration tests start their own throwaway PostgreSQL 17 container through Testcontainers, so Docker must be running.
They never touch your local development database.

## Conventions

- **Workflow:** Jira issue → branch `feature/AUTH-<n>-<short-name>` → TDD → PR → CI → merge → delete branch → Jira Done.
  Every commit message starts with the Jira key (`AUTH-2: ...`).
- **Database changes** only through new Flyway migrations in `backend/src/main/resources/db/migration`.
  Never edit a migration that has been merged.
- **Secrets** come from environment variables. `application.yaml` has no defaults for secrets, so a deployed app without them
  fails at startup. Only `application-local.yaml` has dev-only defaults.
- **Time:** the server runs in UTC. Only the UI converts to local time.
